VineChat Futoon v0.3.2 panel audit

Observed screenshots:
- A manual lookup action stretched to fill the content column.
- Footer actions and navigation were clipped below the physical screen.
- The unrecognized merchant state appeared twice.

Source findings and final changes:
ChatActivity custom measurement gave the added MATCH_PARENT child the full
parent height, then custom layout placed it below the action bar. The panel
now uses parent height minus that offset and the current max system/IME inset.
FutoonPanelLayout is used directly by the native container and sheet sizing.
The sheet's preferred minimum can no longer overflow short available space.
The root clips its children, including zero-height available windows.

The shared prototype block-button flex rule grew vertically in a column.
Direct content buttons no longer grow, and the primary manual lookup action
is in the fixed footer. Header labels and buttons fit narrow widths. The
unrecognized group state is compact and does not repeat its source badge.

Manual query labels clearly say Query merchant. Invalid identifiers are
rejected, no-match retains the form and input, and focused Cancel works in one
click, including return from an unsuccessful ordinary-group lookup. Dirty form discard returns to the requested tab. Back restores scroll.
Login retains transient password/captcha input through asynchronous renders,
clears passwords after successful login, and clears backend business state on
logout/change. Search fields support Enter without submitting financial forms.

Updates coalesce per animation frame. Identical markup does not rebuild the
DOM. Input focus, selection and content scroll are preserved. Keyboard-sized
viewport changes reveal the focused input. Notices sit above footer actions
and are cleared when navigating to another chat.

Native image previews use Telegram's bounded, orientation-aware decoder and
preserve alpha. Original receipt files remain the sending source. Native image
picker, editor and restore callbacks guard conversation generations and file
identity; failed picker launches release the pending request. Destroy tolerates
an already-detached root. These native image paths received source review and
Java compilation, not device instrumentation tests.

Validation scope:
- 132 business/query/identity/monitor/editor checks with local HTTP fixtures.
- 45 native geometry checks, including portrait, landscape, system bars, IME,
  very short windows, and the previous MATCH_PARENT overshoot condition.
- Startup color regression, including an original-crash negative control.
- Browser UI regressions for merchant/order/balance/receipts/OCR/batch,
  channels/monitor/routes/plugins/dark theme, plus ordinary group/no match,
  focused Cancel, dirty navigation, captcha/password retention, unchanged DOM,
  notices, and 393x712, 393x416, 320x330, 844x240 layouts.
- Generated ordinary-group, manual-query and login screenshots were inspected.

No real merchant financial operation or Telegram send was performed.
No real-device launch, FPS benchmark, or Android IME instrumentation was run.
