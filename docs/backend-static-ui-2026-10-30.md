# 原生金融后台界面重构

依据用户要求，以两张静态生成图作为视觉方向，还原到现有 Jetpack Compose 组件中。所有金额、商户与日期在设计图中均为演示数据。原生界面继续读取真实后台字段，不加入图片中虚构的申请人或统计值，也不把图像作为可点击界面使用。

## 共用组件

单层深色标题栏承载返回、当前页操作和悬浮窗控制。五个底部业务入口沿用原路由标识与用户顺序，管理入口仅更换显示名称与图标。页内分类采用文字与细指示线，保留完整点击区域、横向滚动、大字号与 RTL 支持。默认文字、间距、输入边框和 8dp 按钮圆角统一；自定义主题仍通过原调色板传入。

列表使用平面记录与分隔线，金额和币种独立标清，状态始终带文字。详情按信息关系分节，长内容使用可滚动原生页面。加载、无结果、失败、无权限、提交中、结果不明继续使用现有真实状态；不为填充图稿制造指标或成功率。

## 五个业务入口

| 页面 | 交互与信息组织 | 保留的业务边界 |
| --- | --- | --- |
| 识别 | 输入、校对、结果三阶段；明确粘贴按钮；编号与类型可编辑；全选后查询；历史、收藏、凭证草稿及结果工具进入菜单 | 粘贴不自动提取或查询；OCR/二维码、停止未执行项、失败重试、异常汇总、导出和受限批量通知继续保留 |
| 订单 | 可见快速查询与单一筛选入口；紧凑订单、金额、状态和时间；页级指标进入“本页统计” | 通道统计保留官网/当前页样本来源；详情与退款、通知、冻结、凭证等确认链路不变 |
| 商户 | 默认进入全部商户列表，当前会话仍可切换；余额分币种；操作集中在菜单；页级概览移入二级面板 | 资料、用户组、余额、账户/支付/结算权限、密钥与关联业务入口保留；写入继续校对目标和确认 |
| 结算 | 列表优先展示商户、申请金额、状态和时间；到账金额及手续费在详情明确展示；原因优先；关联商户在菜单 | 新后台状态与可用操作限制保持，结算中不开放手动状态操作；审核依据不预填内部标识，结果不明不重放 |
| 管理 | 分组目录和查找；模块图标各自对应语义；资金、黑名单、监测等记录采用统一平面样式 | 原菜单模块、解析、表单与动作保留；敏感值隐藏与空白保留原值的规则不变 |

用户组编辑用基础、支付配置、结算三个栏目。不同支付方式分别编辑，全部隐藏字段和值仍由原表单与原内存草稿管理。切换栏目、收起面板保留未提交输入；取消后清理；保存前核对目标；结果不明不能重复创建。

商户统计直接显示支付方式/支付通道切换，使用后台返回的列与日期。零交易项可恢复显示。商户详情避免重复展示余额与权限，单一可用币种不额外占用一排选择器。

## 验证

真实原生渲染与业务回归覆盖导航、大字号/RTL、筛选、历史/收藏返回、粘贴不自动查询、识别选择、用户组跨栏目与面板草稿、取消、防重放、结算限制和分币种展示。业务回调清单只更新本轮已审查的导航、菜单、查询与本地输入回调。

服务器写入使用拦截传输响应验证；生产环境验证只读、打开后取消。最终验收要求实际 APK 核验、覆盖安装及真机逐页验证，不能用本地渲染或设计图替代。

范围仍不包含暂缓的两项隔离通道问题，以及 Telegram 聊天首页四个固定按钮。聊天、群自动化、金融接口和权限策略不因本轮界面重构改变。

## 本轮新增：余额管理与聊天订单入口

余额管理按照官网实际使用的 [admin-balance.js](https://1.futo-on.com/assets/js/admin-balance.js?v=20261027-3) 适配。先读取最新余额快照、安全上限、操作凭证和操作编号，支持充值、扣除、冻结、解冻及解除具体提现申请；原因限制为 3–200 个 Unicode 字符，金额按官网分别限制两位或六位小数。解除申请使用服务端释放金额与申请版本，不能在客户端自由填写释放数额。原生商户列表与识别页共用一个编辑器，旧后台保留原增减接口。

提交之前把不可变请求保存到按 Telegram 账号、后台和商户隔离的加密记录。连接中断或未知结果保留记录，刷新不清除；明确选择查询/安全重试时使用原操作编号、原金额与原原因，只更新服务器凭证。存储失败不发请求，存储无法解密也不能当成空记录继续。Telegram 调用层必须先取得余额编辑票据；旧的直接传金额方式在新后台被阻止。

当前聊天最近约二十条消息可沿用本地识别规则提取订单线索。识别只传候选编号到已经配置的后台做只读精确查询，不上传完整聊天文字，不跨会话或话题扫描。重复编号合并查询；只有唯一订单结果才在原文字上加本地可点击标记，保留其他链接与原消息内容。点击后重新读取当前订单，再直接显示其可用操作；退款、通知和状态变更仍走原确认及结果不明保护。离开会话时移除标记，过期结果不能应用到新会话。保护消息、秘密聊天和无法安全映射文字位置的消息跳过，仍可使用原手动识别流程。

本地验证：437 项测试通过，零失败/错误/跳过；375 个业务点击回调和 147 个安卓 ICU 正则检查通过。测试截图使用隔离演示数据。此处记录本地结果，构建、安装和真实聊天点击验收必须另外记录，不能据此声称真机已经通过。生产余额、提现解除、付款、审核、作废与冻结未执行写入。

补充核对：未确认的提现解除显示原操作释放金额，不能用刷新后的金额替换。此小项修正后，4 项余额界面专项重新通过；整批回归记录仍单独保留为 437 项通过。
