# 群自动化与聊天订单快捷入口补修

用户反馈：规则中不需要发送者 ID，留空保存却出现 `For input string: ""`；需要一条规则多选群组；聊天中订单快捷操作没有效果。

## 群规则

发送者 ID 选填，留空保存为 0，表示不限定发送者。选择群组、关键词、话题和按钮名称仍按配置匹配；按钮执行时以消息的实际发送者核验机器人身份，拒绝普通用户、广播频道、链接按钮、需要密码的按钮和重复按钮名。

原生群选择器支持勾选 1–50 个普通群或话题群，点右上角确定统一返回。再次打开带回已选群组，取消不改规则草稿。每个群可各自限定话题，0 为全部话题。旧版单群配置继续读取，启用状态、启用时间和执行防重记录不重置。草稿变量使用实际触发群和发送者。

设置流程：新增/编辑规则 → 选择群组并勾选 → 确定所选群组 → 确定规则 → 开启规则 → 保存设置。新增规则默认关闭。

## 聊天订单

Telegram 对加粗、代码等实体重新排版时，会删除重叠的 URLSpan。原实现先插订单链接再排版，链接因此被删除。现在将已核验的订单标记按消息保存，在实体处理完成后、文本布局生成前恢复；图片说明文字也使用同样的恢复方式。未经唯一精确查询的编号不会添加订单操作。

仅对后台精确匹配的完整编号替换 Telegram 自动识别的电话链接，离开会话时恢复原电话链接；原有网站链接保留。换账号、后台、会话或消息内容变化后不复用动作。首次查询失败不再永久记成已扫描；限次延迟重试，不改变业务写入行为。

## 验证

本地整轮 446 项通过；最后补充原电话链接恢复后，4 项标记回归和 lint 再次通过。群自动化实际 Java 调度器 28 项检查通过，另执行实际原生选择器的普通群/论坛群勾选、取消、类型与数量上限检查。宿主补丁、回调审查、ICU 正则及原有核心检查通过。

这些是本地和拦截传输验证，不代表已在用户手机通过。新包需云端构建、下载并核验后发送 Telegram 收藏夹；由用户手动安装。
