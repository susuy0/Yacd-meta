# 移动后台界面收敛

这是对当前原生后台的实作约束，不增加装饰性仪表盘，也不重新定义资金接口。

参考公开的一手规范：

- [Coinbase：数据表与跨平台](https://cds.coinbase.com/components/data-display/Table/) 建议复杂数据在手机使用列表；本轮采用可扫读的摘要行与独立详情。
- [CFPB：金融数据表格](https://cfpb.github.io/design-system/components/tables) 强调准确的标签与单位。金额、实际到账、币种、状态与限制不能因精简而混为一项。
- [Carbon：数据列表](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) 采用按需展开、集中工具栏与选中后出现的批量操作。这里采用其交互原则，并保留移动端至少 48dp 的触控区域。

## 处理范围

管理页使用分组列表和查找；全局管理页不显示无关会话提示。列表统一中性标题与间距，颜色集中用于选中、主操作和真实状态。数字与状态优先，重复说明、重复 ID 和内部结果码退出摘要区。

资金明细、黑名单把展开入口并入记录标题。统计采用并列的商户与合计摘要；有交易的明细按需展开，零交易项仍能显式查看，原始数值不丢弃。无流水商户保留近期订单与账户状态，注册时间收进详情，未命中的白名单不占一行。统计查询合并为一行日期与查询按钮，统计方式放入筛选菜单。新增必填密钥不再显示“留空保留现有值”的误导说明。结算的关联商户入口收进操作菜单；原生宿主只保留一个完整搜索入口。

用户组的编辑读取官网 `getGroup` 顶层 JSON，再按网页表单填入原组名称、各支付方式的通道、路由类型、分成比例、投诉处理与结算设置。通道选项携带的路由类型必须同步更新；已有分成比例不被选项默认值覆盖。编辑页按支付方式与结算设置分节展开，取消和保存固定在底部，保存前确认目标组。新增表单不得借用上一组的值，名称为空不可保存。未保存输入只在本机内存保留，收起面板再打开不丢失；取消、保存成功或明确重新读取后清理，不落盘或带入另一个用户组。保存结果未确认时阻止重放；新增结果不明时回列表核对，不能靠刷新空表单重复新增。

## 验证边界

生产环境仅读取、打开编辑页和取消。保存、删除、审核、冻结等写入用拦截传输的测试响应验证。本轮没有修改生产用户组或资金数据。隔离通道相关两项继续暂缓；聊天首页四个固定筛选按钮仍只记录。
